The noop reference pipelines — light and heavy

noop and noop_baked are the platform's two reference modules. Neither runs real science — each carries an input through the full pipeline and back so a returning card proves the wiring. Light (noop) computes inline on the GitHub runner and writes the result straight to Postgres. Heavy (noop_baked) runs on an ephemeral EC2, stores the payload in S3, and writes a pointer to it — the template every real EC2-scale module reuses. Both share the same rails, tables, and token-gated lifecycle below.

Row-level security. Reads (4, 9) run under current_org_id(). The writes in step 8 are SECURITY DEFINER RPCs that bypass RLS — authorized by the per-job token and its expiry, not the user session. service_role never leaves Postgres.

The jobs.envelope row collapses the machine-written execution columns — instance_id, the S3 URI pointers, cost, error_class/detail, and the dispatch/start/finish timestamps. Light noop leaves the S3 and cost columns null; heavy noop_baked populates instance_id and the S3 pointer, the same columns a real EC2 module writes.
